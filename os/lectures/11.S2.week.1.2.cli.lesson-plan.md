# Lesson Plan: Introduction to the Linux Command Line

**Subject:** Computing / IT  
**Level:** Introductory (no prior Linux experience assumed)  
**Duration:** 3 hours (can be split into two 90-minute sessions)  
**Platform:** Fedora Linux workstations — students do not have sudo or root access  
**Class size:** Up to 30 students  

---

## Learning Objectives

By the end of this lesson, students will be able to:

1. Navigate the Linux filesystem confidently using `pwd`, `ls`, and `cd`
2. Create, copy, move, view, and delete files and directories
3. Read and interpret Unix permission strings, and change permissions on their own files
4. Use `grep`, pipes (`|`), and redirection (`>`, `>>`) to process text
5. Search for files using `find`, `which`, and `whereis`
6. View and manage running processes using `ps`, `top`, and `kill`
7. Verify file integrity using `md5sum` and `sha256sum`
8. Find help independently using `man`, `--help`, and `cheat`
9. Write and execute a simple shell script
10. Explain why the CLI is a valuable skill alongside graphical tools

## Detailed Lesson Plan

### Part 1 — Introduction & Motivation (15 min)

**Goal:** Get students curious and remove the fear of the CLI.

- Open with a question: *"Has anyone used a terminal before? What did you think of it?"*
- Show slide 1 (title) and briefly explain what students will be able to do by the end of the session.
- Show slide 4 (Why Use the CLI?) and discuss each point — speed, automation, remote access, power, universality.
- **Discussion prompt:** Ask students to think of a task they do repeatedly on a computer. How might they automate it? (Don't answer yet — plant the seed for scripting later.)
- Show slide 5 (Anatomy of a Command) and walk through `command [options] [arguments]` with `ls -lh /home/student` as an example.
- Explain the prompt: `$` = regular user, `#` = root. Emphasise that they will always see `$` today.

**Key point to land:** The CLI is not a replacement for the GUI — it is an additional tool that becomes invaluable for certain tasks.

---

### Part 2 — Navigation & Working with Files (30 min)

**Goal:** Students understand the Linux directory tree and can move around and manage files.

#### Navigation (10 min)

- Show slides 6–7 (Navigation, Directory Tree).
- **Live demo** in a terminal (project on screen):
  ```
  pwd
  ls
  ls -lh
  ls -a
  cd /etc
  ls
  cd ..
  cd ~
  ```
- Draw the directory tree on the whiteboard or reference the diagram in the slides. Emphasise that Linux has one tree rooted at `/` — no C:\ or D:\ drives.
- Point out the key directories: `/home`, `/etc`, `/var`, `/usr/bin`, `/tmp`.

#### Files & Directories (10 min)

- Show slide 10 (Create, Copy, Move, Delete).
- **Live demo:**
  ```
  mkdir demo
  cd demo
  touch hello.txt
  echo "Hello world" > hello.txt
  cat hello.txt
  cp hello.txt backup.txt
  mv backup.txt saved.txt
  ls -l
  ```
- Highlight the `>` vs `>>` distinction — demonstrate both live.
- **Safety moment:** explain `rm` and that there is no Recycle Bin. Show the warning on the slide. Tell students they will not be asked to delete anything important today.

#### Viewing Files (10 min)

- Show `cat`, `head`, `tail`, `less` with `/etc/passwd` as a real-world example.
- Demo `less` with keyboard shortcuts: Space, `b`, `/`, `n`, `q`.
- **Comprehension check:** Ask students: *"If a log file has 50,000 lines, which command would you use and why?"*

---

### Part 3 — Permissions & Text Processing (25 min)

#### Permissions (12 min)

- Show slide 11 (Permission Strings).
- Walk through `-rwxr-xr--` character by character with the diagram.
- **Live demo:**
  ```
  ls -l /etc/passwd
  ls -l /etc/shadow
  ```
- Ask students: *"Why can you read /etc/passwd but not /etc/shadow?"* — let them reason it out from the permission string before explaining.
- Demo `chmod`:
  ```
  touch secret.txt
  chmod 600 secret.txt
  ls -l secret.txt
  chmod 644 secret.txt
  ```
- Explain the numeric shorthand (4=read, 2=write, 1=execute). The full explanation is in the lecture notes if students want to go deeper.
- Explain `sudo` briefly — they won't use it today, but they will see it in real-world commands. It runs a single command as root and leaves an audit trail.

#### Text Processing & Pipes (13 min)

- Show slide 13 (Text Processing & Pipes).
- Introduce `grep` — *"Find lines that match a pattern."*
- **Live demo, building up the pipeline step by step:**
  ```
  grep "bash" /etc/passwd
  cat /etc/passwd | cut -d: -f1
  cat /etc/passwd | cut -d: -f1 | sort
  cat /etc/passwd | cut -d: -f1 | sort | uniq
  cat /etc/passwd | cut -d: -f1 | sort | uniq | wc -l
  ```
- Narrate each step as you add to the pipeline. Emphasise that each command does one small thing — the power comes from combining them.
- **Key concept:** Output of one command → input of the next. *"Think of it like an assembly line."*
- Show redirection: `grep "bash" /etc/passwd > bash_users.txt` and then `cat bash_users.txt`.

---

### Part 4 — Finding Things, Processes & Help (20 min)

#### Finding Files (7 min)

- Show slide 14 (Finding Things).
- **Live demo:**
  ```
  find ~ -name "*.txt"
  find /etc -name "*.conf" | wc -l
  which python3
  whereis grep
  ```
- Contrast `find` (live search) vs `locate` (pre-built index) — mention that `locate` may or may not be on their machines.

#### Processes (7 min)

- Show slide 15 (Processes).
- **Live demo:**
  ```
  ps aux | grep $USER
  top
  ```
- In `top`, show how to sort by memory (`M`) and how to quit (`q`).
- Demo background jobs:
  ```
  sleep 60 &
  jobs
  kill %1
  ```

#### Getting Help (6 min)

- Show slide 16 (Getting Help).
- **Demo all three side by side** on the same command (`grep`):
  - `man grep` — scroll to DESCRIPTION, search with `/`, quit
  - `grep --help | head -20`
  - `cheat grep` (or `curl cheat.sh/grep`)
- **Ask students:** *"Which of these would you reach for first as a beginner? As an expert?"*
- Mention `cheat.sh` works in any browser — useful when no cheat client is installed.

---

### Part 5 — Checksums (10 min)

- Show slide 17 (File Integrity & Checksums).
- Explain the concept: *"A hash is like a fingerprint for a file. Change one byte and the fingerprint completely changes."*
- **Live demo:**
  ```
  echo "hello" | md5sum
  echo "Hello" | md5sum
  echo "hello" | sha256sum
  md5sum /etc/passwd
  sha256sum /etc/passwd
  ```
- Demonstrate the avalanche effect — change one letter and the whole hash changes.
- **Real-world context:** When you download a Linux ISO, the website publishes a SHA-256 hash. You run `sha256sum -c CHECKSUM` to confirm the download is genuine and uncorrupted.
- Briefly note: MD5 is fine for corruption checking; use SHA-256 for anything security-sensitive.

---

### Part 6 — Guided Worksheet Lab (60 min)

**Goal:** Students work through all 11 exercises on their Fedora workstations, recording observations and answers.

- Distribute (or open) the worksheet: `linux_cli_worksheet.docx`
- Students work at their own pace through Exercises 1–10.
- **Instructor role during lab:**
  - Circulate the room — do not just sit at the front.
  - Watch for students who are stuck on the same step for more than 3–4 minutes — offer a nudge rather than the answer.
  - Common sticking points to watch for:
    - Forgetting `cd ~` before starting a new exercise
    - `Permission denied` on `/etc/shadow` — this is intentional, not an error
    - Confusion between `>` and `>>` (they often discover this by accident, which is fine)
    - `./hello.sh: Permission denied` before `chmod +x` — a good teachable moment
- **Suggested pacing check at 30 min:** Announce where students should be by now (Exercise 5 or 6). Students who are ahead can start the Mini Challenges.

#### Suggested Checkpoint Questions to Ask the Room

- *"What does the pipe symbol actually do?"* (After Exercise 5)
- *"If you ran sha256sum on a file yesterday and the hash is different today, what does that tell you?"* (After Exercise 9)
- *"How many programs are in /usr/bin on your machine?"* — students compare answers across the room.

---

### Part 7 — Mini Challenges & Debrief (20 min)

#### Mini Challenges (10 min, independent)

- Students who finish Exercises 1–10 attempt Exercise 11 (Mini Challenges).
- The four challenges require combining skills from across the worksheet:
  1. Count `.conf` files in `/etc` with a pipeline
  2. Extract and sort usernames from `/etc/passwd`
  3. Generate and verify a SHA-256 checksum
  4. Write a shell script `info.sh`
- Encourage students to use `cheat` or `man` rather than asking the instructor for syntax help.

#### Class Debrief (10 min)

- Ask volunteers to share their answer to **Challenge 4** (`info.sh`) — live-run a few scripts on the projector.
- Return to the opening discussion prompt: *"Remember the repetitive task I asked about earlier? Could you automate it with a script now?"*
- Work through the **Reflection** questions verbally as a group — or have students share with a partner.
- **Closing points:**
  - The CLI has a learning curve, but the skills compound — every command you learn makes the next one easier.
  - `cheat.sh` exists. Use it. Nobody memorises flags.
  - The best way to get better is to use the terminal for real tasks — not just in class.

## Differentiation

### Students who finish early
- Attempt all four Mini Challenges
- Write a more complex script: print a summary of the system (hostname, uptime, current user, number of files in home directory)
- Explore `cut -d: -f3 /etc/passwd` — what are those numbers? (UID/GID — leads naturally into a discussion of user IDs)
- Try `cat /proc/cpuinfo` and `cat /proc/meminfo` — what information can you find about the hardware this way?

### Students who need more support
- Focus on Exercises 1–5 only and ensure those are solid
- Pair them with a student who is progressing well
- Refer them to the lecture notes document for fuller explanations and examples
- Encourage use of `cheat <command>` when stuck — reinforce help-seeking as a skill

### Extension topics (if time allows or for advanced groups)
- SSH: `ssh user@hostname` — connecting to a remote machine
- `cron` jobs — scheduling commands to run automatically
- `awk` and `sed` — more powerful text processing
- Writing scripts with arguments: `$1`, `$2`
- `tar` for creating and extracting archives

## Common Misconceptions to Address

| Misconception | Clarification |
|---------------|---------------|
| "The CLI is just for hackers / experts" | Every developer, sysadmin, and data scientist uses it daily — it is an industry-standard tool |
| "I need to memorise all these commands" | Nobody does. `man`, `--help`, and `cheat` exist precisely because there are too many flags to memorise |
| "If I make a mistake I'll break the system" | Without sudo, students cannot damage system files. The worst that can happen is deleting their own files — and we warn them about `rm` explicitly |
| "rm just moves things to a Trash folder" | No — `rm` is permanent. Emphasise this clearly and demonstrate before students reach Exercise 2 |
| "The shell and the terminal are the same thing" | The terminal is the window; the shell (bash) is the program inside it that interprets commands |

## Technical Setup Checklist

Before the session, verify on at least one lab machine:

- [ ] Students can log in with standard (non-root) accounts
- [ ] A terminal emulator is accessible (GNOME Terminal, Konsole, or similar)
- [ ] `/etc/passwd` is readable: `cat /etc/passwd`
- [ ] `/var/log` exists and contains at least one readable log file (e.g. `dnf.log`)
- [ ] `find`, `grep`, `wc`, `cut`, `sort`, `head`, `tail`, `less`, `chmod` are available (all standard on Fedora)
- [ ] `cheat` is installed: `cheat ls` — if not, confirm `curl` is available as a fallback: `curl cheat.sh/ls`
- [ ] `md5sum` and `sha256sum` are available (standard on Fedora)
- [ ] `locate` availability is noted (it may or may not be installed — the worksheet handles both cases)
- [ ] Students' home directories exist and are writable

## Notes for the Instructor

- **Don't rush the pipe section.** The concept of chaining commands is the single biggest "aha moment" of the lesson, and it takes a few minutes to click. Build the pipeline one command at a time on the projector and narrate each step.
- **Model good help-seeking.** When you demo a command you haven't used in a while, deliberately look it up with `cheat` or `man` in front of the class. This normalises using documentation and makes it less intimidating.
- **Expect `/etc/shadow` Permission Denied.** This is intentional and a great teaching moment about why permissions matter. Tell students to check the permission string themselves — it is right there in `ls -l`.
- **The `chmod +x` moment in Exercise 4** is one of the best hands-on permission demonstrations. Let students hit the `Permission denied` error before explaining — the frustration followed by the fix is memorable.
- **Checksum avalanche effect** is worth dwelling on briefly. Students are often genuinely surprised that changing one character produces a completely different hash. A little theatre helps: *"What if I change just the capital H to a lowercase h?"*
